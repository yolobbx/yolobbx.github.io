最近一周左右几乎每天都在用 AI Agent 干活,虽然时间不长,但踩了不少坑也摸出了一些路子,趁记忆还新写一篇总结。

## 为什么是 Claude Code

我同时试过 OpenAI 的 **Codex** 和 Anthropic 的 **Claude Code**,两边各有长处:

- **Codex** 在纯代码补全和单文件改动上很稳,响应也快,适合"我知道要改什么、就差一双手"的场景。
- **Claude Code** 在跨文件理解和长链路任务上更顺,而且——这是我最在意的一点——**审美更强**。它写出来的代码风格、命名、注释取舍,以及涉及前端时的页面布局和配色,默认值都更接近"一个有品位的人会怎么做"。

我个人最后落到 Claude Code 上,主要是因为我做的事偏向多文件协作 + UI/前端 + 写作,审美这一项的权重很高。如果你是纯写后端逻辑或脚本,Codex 也完全能打。

## 国内怎么接入:中转站方案

Anthropic 官方在国内是用不了的,信用卡支付那一关基本卡死大部分人。我用的方案是**中转站**——把请求转发到一个第三方网关,付人民币就能用。

### 踩过的坑:不要充太多

之前在淘宝买过一家,5 块钱给 100 刀的额度,看着特别划算,我一口气充了几次。结果用了一阵子站长自己跑路了,余额清零。

教训很简单:**中转站本质是个人或小团队在运营,随时可能没**。所以原则就一条——

> 用多少充多少,绝对不囤额度。

哪怕单价贵一点,也比一夜之间归零强。

### 我现在用的:FreeModel

后面换到了 [FreeModel](https://freemodel.dev/invite/FRE-76805d9c),用我这个链接注册能送 10 刀额度,够你试用感受一下值不值得继续。

它现在有个 **Pro 会员**(我目前在用):

- 每 7 天给约 **66 刀** 的额度
- 用量限制是**滚动窗口**:每 10 小时最多消耗 10 刀

10 小时 10 刀这个限制,实际用下来是这样:写代码、对话、跑跑 Agent,如果不是连续高强度跑大任务,基本撞不到上限。重度用户(比如让它整天不停地跑长任务)会感觉紧,正常使用绰绰有余。

具体怎么把 Claude Code 指到中转站,FreeModel 官网文档里有,大致就是设两个环境变量(`ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN`),非常简单。

## 为什么用终端版

Claude Code 有桌面版、网页版、IDE 插件、终端版,我选的是**终端版(CLI)**,理由:

- **极客**。我大部分时间都在终端里干活,AI 在同一个窗口里,上下文流畅。
- **轻量**。后台跑一个 node 进程而已,不像 Electron 桌面 app 那么吃内存。
- **配置可控**。所有配置就是几个文件,可以版本化、可以同步到新机器。

为了让终端用着顺手,我之前花了点时间把 Mac 的终端栈整个配了一遍——zsh、Oh My Zsh、Powerlevel10k、fzf、zoxide、Ghostty 这些。详细写在了 [Mac 终端配置:从零到顺手](/posts/mac-terminal-setup/) 那篇里,想跟着配的话可以看那篇。

## 工作流:给 AI 一个专属文件夹

我的用法很简单:**给 AI 单独建一个文件夹**,所有让它干的活儿都在这个文件夹里发生。增删改查都在这里,出问题最差就是把整个文件夹删了重来,不会污染其他项目。

```bash
mkdir ~/ai && cd ~/ai
claude
```

进去之后就可以让它干活了。它要读什么、写什么、跑什么命令,都会先弹出来问你。

### 三种工作模式

Claude Code 有几种自动化程度不同的模式,按 `Shift+Tab` 切换:

- **Default**:每个动作都问你一次,适合不熟的时候。
- **Accept Edits On**:文件编辑直接放行,不再每次问;但跑 Bash 命令还是会问。我日常用这个。
- **Plan Mode**:只规划不动手,适合你想先看看它打算怎么干。

### 权限记忆

每次它要跑一个 Bash 命令,会弹两个选项:

- **Allow once**:这次同意,下次还问
- **Allow always**:这次同意,以后这个命令不再问

第二个选项会把命令写进 `.claude/settings.json` 的 allowlist。用得多了之后,常用命令(`ls`、`git status`、`npm run build` 这些)都进了 allowlist,就基本不被打断了。

但**有破坏性的命令**(`rm -rf`、`git push --force`、`brew uninstall` 这些)我从来不勾"always",每次都让它问一遍。多花两秒确认,比误删整个目录强得多。

## Skill 和斜杠命令

在对话框里输入 `/` 会弹出一堆功能,这是 Claude Code 的"扩展系统":

- **斜杠命令**:`/init` 给项目生成 CLAUDE.md、`/clear` 清空上下文、`/model` 切换模型(Opus / Sonnet / Haiku)等等。
- **Skill**:打包好的工作流。比如 `/init` 写文档、`/security-review` 做安全审查、`/verify` 跑代码验证修复有没有生效。

不需要专门去学怎么用——**问它本身就行**。

> "我现在在终端里,你都有哪些斜杠命令?分别什么时候用?"
>
> "这个项目我想加一个 Skill 来管理 commit 流程,怎么搞?"

它会一条条讲清楚,需要的时候还会帮你直接装上、配好。

### 递推学习法

我管这个叫**递推学习法**——一个东西不会用,就让它自己教你下一步;学会一步,再让它带你下一步。一层一层往前推:

- 想装个 Skill?让它去找、去装。
- 不知道某个命令干嘛的?让它解释。
- 想换个模型?让它告诉你怎么 `/model`。

这个方法的核心前提是:**你得舍得花时间和额度**。前期会有一些"问 AI 怎么用 AI"的对话看上去像浪费 token,但摸熟之后效率提升远不止这一点开销。## 我用它做了什么

到目前为止,我用 Claude Code 完成过的项目大致是这些:

- **iOS 开发**。一个完整的小 app,从 SwiftUI 界面到 CoreData 存储到 App Store 上架前的打包,整个过程我基本只做产品决策,代码大部分由它写。
- **一些小工具**。日常需要的脚本、自动化任务、数据处理工具,从想法到能跑大概几十分钟。
- **这个博客本身**。Astro 框架的选型、页面布局、样式调整、Jekyll 到 Astro 的迁移,都是跟 Claude 边讨论边搭出来的。当然不是我说一句它就闷头干——更像是结对编程,我提需求,它给方案,我们来回对几轮,最后定下来再让它实现。

需要强调的是:**它不是替你思考**。设计决策、产品方向、什么功能该有什么不该有,这些还是你的事。它解决的是"想清楚之后,怎么把它落地"这一段——而恰恰这一段,在没有 AI 之前是最耗时间的。

## 一些建议

最后几条我自己总结的经验:

1. **从小项目开始**。先用它做点不重要的事,熟悉它的脾气。
2. **多用 Plan Mode**。重要改动让它先讲方案,你看完再 OK。
3. **别迷信**。它写出来的代码该 review 还是要 review,尤其是涉及钱、权限、数据库的部分。
4. **保留对话历史**。`/resume` 能找回之前的会话,做长项目很有用。
5. **学会打断**。觉得它跑偏了,直接 ESC,别等它跑完一大段才发现方向错了。

---

总的来说,只要你有相对充足的时间和额度去试,AI Agent 真的能改变你的工作方式。我现在已经回不去那种"什么都自己写、自己查文档、自己 debug"的状态了——不是不行,是没必要。
